# Changelog

## 1.97 (published as v.1.97, `OutyDS_1.97.apk`)
- ELM327 adapter initialisation (for clones that failed here but work in PHEV Watchdog): a space is sent before `ATZ`, the pause after `ATZ` is 500 ms, `ATCAF1` is no longer required to succeed, and `ATST` becomes `C8` instead of `64` only if some init command needed a retry (slow adapter). Fast adapters are unchanged. Not tested with a Konnwei adapter.
- Tyre position by sensor ID (Settings > tyre mapping): optional hex ID per wheel. For ECU 600/500 frames the app records bytes 2–7 of each reply as the slot's ID and, when your ID is found in it (either byte order), assigns that slot to the wheel. Empty fields or no match = the existing pressure-test mapping, unchanged. Which bytes are the real sensor ID is not confirmed; the detected IDs are listed under the fields. Logic checked with mock frames only.
- Disconnect loop with the engine ECU silent (found in a console log: reconnect about every 60 s): the extended 7E0 queries (210E/210F/2112/211A) each wait 4 s for a timeout, four in a row = 16 s, which the 15 s polling watchdog treated as a stall and reset the Bluetooth link. Now the watchdog timer is refreshed after every such query, and a timeout/no-answer ends that round of queries (one 4 s wait instead of up to four). Only that routine changed. Checked from the log; not re-run on the car.
- VIN: read once (first connection after the app starts, or again only if that read failed); automatic Bluetooth reconnects no longer re-read it (the read could block polling for up to 8 s). The manual "Read VIN" button is unchanged.
- Polling watchdog: if the adapter has answered within the last 5 s, a stall now re-initialises the adapter over the existing Bluetooth link (first three stalls in a 2-minute window); the Bluetooth link is dropped and reconnected only if the adapter is silent or stalls keep repeating. Poll order and timing are not changed. Not run on the car.
- Translations completed in Romanian and English: the ~137 OBDb signal names and the standard PID names (Romanian when the app language is Romanian; CSV exports keep English names), the performance-monitor and diagnostics report labels, icon tooltips and aria labels, the OBDb group names, the Remote tab (it now follows the app language instead of the phone language, and reloads after a language change once no car session is active) including its WiFi/permission/alarm messages and the English-only native WiFi messages, the Android notification channel name "Scheduled preheat" (only new installs, Android keeps the name of an existing channel), the snapshot reason labels and the settings label for the GitHub repo. Also fixed the report header showing version 1.96. Debug-log lines and protocol traces stay English. Checked in Romanian and English with a browser mock; the native strings were only assembled, not run on a phone.
- Dash (Tablou): tapping a tyre value switches psi/bar, same setting as on the Flow page. Only the click handler and a pointer cursor were added. Checked in a browser mock only.
- Settings: "Keep the screen on while connected" and "Dim the screen" (window flag and window brightness; no extra permission). Applies only while the state is connected. Not tested on a phone yet.
- Battery condition: shows the BMU lifetime counters for charge through AC/DC and DC/DC (Ah), previously only in the exported report. What each counter physically covers is taken from the PHEV Watchdog labels, not verified separately.
- In-app updater: the release's `SHA256SUMS` is downloaded first (no `SHA256SUMS` in the release = no install); the APK is saved in the app's private folder and checked before the installer opens (SHA-256 against `SHA256SUMS`, same package name, higher versionCode, same signing certificate as the installed app); a failed check deletes the file and shows a message. The JavaScript part was run against a mock; the native (smali) part was only assembled, not run on Android.
- Privacy: the serial part of the VIN (last 6 characters) is hidden in exported CSV/JSON reports, the OBD console export header and the Remote log lines; the Remote log file is capped at about 2 MB per session; WebView content access is switched off (nothing in the app uses `content://` pages).
- Settings > Diagnostics: a new "OBD connection" card (state, time connected, time since the last adapter message and the last vehicle data, disconnect and reconnect counters, last error event, and a plain explanation: adapter disconnected / link up but adapter silent / adapter answers but the car sends no data). Built from counters the app already kept. Checked in a browser with mocked state, not on a car.
- Content-Security-Policy added to `index.html` and `remote.html`. Checked in desktop Chromium (page, tabs, dashboard, worker, Remote iframe load without violations; inline script and other hosts blocked), not in Android WebView.
- About screen text (RO/EN) now states the targeted model years (2013–2018) and that only logs from one 2016 car were checked; Romanian typo "Activeaz-o" corrected; Romanian label of the battery health tab aligned with the English one.
- Documentation: consistent naming (OutyDS = application, Outy = repository), "WiFi" spelling, vehicle-compatibility section, clearer wording on what logs and screenshots can contain, release status no longer repeated in several files.
- Battery health (SOH): the nominal capacity is now chosen per car from the VIN model year (40 Ah up to MY2018, 46 Ah from MY2019; US-built MY2019 40 Ah), following the per-model values found in PHEV Watchdog 1.9.1; a value typed in Settings still wins. SOH stays capacity / nominal. Not verified on a car.
- Range: the consumption used for the estimate is 12 % higher (more conservative).
- The notification service is stopped when the app is closed or removed from recent apps (reported on Huawei P30; not verified on that phone).
- Polling speed: when the car's ECU changes, the three adapter set-up commands (`ATSH`, `ATFCSH`, `ATCRA`, plus the flow-control pair when needed) are now sent in the same Bluetooth/TCP write as the request that follows, instead of one round trip each. In a console log from the car, adapter commands were 37 % of the bus time (1569 commands of about 67 ms against 850 data requests). The same commands reach the adapter; only the number of writes drops. Replies are counted per command; if the adapter does not answer all of them in time or answers anything other than OK, the app returns to one command at a time for that connection after two failures (logged as `batched set-up off`). Demo mode is unchanged. Tested with a simulated adapter and with the whole app against a simulated adapter (about 40 % more poll passes in 20 s; an adapter that drops extra commands falls back within a few seconds and keeps working). Not run on a real adapter yet, and the saving on the car is not measured.
- The native bridge check handles several commands in one write (each line is checked separately), so batching does not bypass it.
- Reconnect after a Bluetooth drop: the retry timer now uses the same background timer as the polling loop. In a log, a drop at 15:29 was followed by the retry only 12.5 minutes later, when the app was opened again; the cause is probably that WebView throttles ordinary timers in the background (not confirmed). Not verified on the phone.
- Audit fixes (repository audit of 2026-11-27):
  - The OBD console can no longer send the clear-fault commands (`04`, `14FFFFFF`); only the clear flows in Diagnostics pass an internal write flag. Clearing is also refused when the speed is unknown or older than 5 s (before, only a known speed above 5 km/h blocked it). Unit test added for the command filter (`tests/elm-blocked.test.js`).
  - Native bridge (smali): `write()` now rejects empty or over-long text, characters outside the ELM command set, adapter programming commands (`ATPP`, `ATBR`, `ATM...`), diagnostic write/session services, and `04`/`14...` unless the page armed them within the last 20 s. `PhevBridge.send()` checks length and hex digits and no longer throws on bad input.
  - `PhevBridge.instance` is cleared when the activity is destroyed, so the alarm receiver no longer calls into a destroyed WebView.
  - Location permission: fine and coarse location are requested together (Android 12+ lets the user pick approximate). `NEARBY_WIFI_DEVICES` is unchanged on purpose: it was not changed without a phone to test the WiFi join.
  - The scheduled pre-heat background service holds a timed CPU wake lock (about 21 min at most, released when the service ends).
  - Remote tab: "Clear" now says that only the screen was emptied and the log file in Downloads stays; clipboard messages translated. `remote.html` takes its `lang` from the app language. English About text now says "and any writing", like the Romanian one.
  - Build and CI: `build.sh` and `check-repo.sh` require a numeric versionCode; the release report compares the APK versionCode with the source. The VIN scan in `check-repo.sh` is broader and `.gitignore` covers more key and log file types. Actions in the workflows are still tagged by version, not by commit SHA.
  - None of the smali changes was run on Android; they were only assembled.
- `scripts/check-docs.js` (run by `scripts/check-repo.sh` and CI): version consistency, translation completeness, stale release wording, spelling and relative links.

## 1.96 (published as v.1.96, `OutyDS_1.96.apk`)
- Bluetooth or WiFi OBD adapter, chosen from the Conectare button (WiFi: plain TCP, default port 35000; not yet tested with a real WiFi adapter).
- Data regrouped: Baterie page (energy, charging, trip energy, cells, battery temperatures) and Motor page (trip, engine, ECU signals, electric motors, climate).
- Charge statistics and cost, altitude climb/descent, motor share, SoC and cell alerts.
- TPMS: dead sources are skipped, ECU 600 layout decoded, values expire after 3 minutes, no values kept between sessions (tested in a simulation based on a car log; not yet verified on a car).
- In-app updater (present since 1.95): default repository now set to `cangri-outy/Outy`.
- Trip duration now counts real elapsed time from connection (it was cut to 3 s per OBD pass) and a trip that has not moved yet is no longer reset by the idle auto-split. Checked in a browser simulation only.
- TPMS: the route that answered last time (ECU 600) is remembered and tried first on the next connection. Checked by reading the code and a syntax check; not verified on a car.
- Fix: location permission check in `MainActivity.askLocation()` was inverted (it asked when already granted and marked it granted when denied). Verified by reading the code; not tested on a device.
- Fix: scheduled pre-heating (`PhevBackgroundService`) now uses a persistent receive buffer (`PhevRxBuffer`): partial frames are completed across reads, several frames per read are all processed, leftover bytes are kept and `SecurityKey.update()` receives only the exact 14-byte (or 18/24-byte) start frame. The protocol itself is unchanged. Covered by a Java reference-model test; the smali was assembled but has not been run on a device or a car.
- About screen: copyright/GPL-3.0/redistribution notice, phev2mqtt, OBDb and Open-Meteo attribution; "Weather data by Open-Meteo.com" next to the weather option.
- Release workflows: report takes a tag input and checks package name, version, signing certificate and alignment; download statistics count only `.apk` assets and the dashboard no longer shows multi-day gaps as daily growth; checksum file is generated after the final `OutyDS_<version>.apk` name is chosen.
- GPL-3.0 notice, disclaimer and source published; security hardening (message source checks, escaping, https-only links, updates only from github.com).
